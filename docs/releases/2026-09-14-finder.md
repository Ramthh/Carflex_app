# Carflex Finder updates — 14 September 2026

Finder now includes every public Facebook listing available through its integration, with separate New Est. and Old Est. deal labels, posting/discovery times, and faster live updates. New cars remain visible while additional source details are collected.

## Website changes

- Added authenticated Finder access, responsive Grid/List views, and links from car photos to their Facebook ads.
- Expanded inventory beyond the previous seller-category and completed-detail filters. Private imports remain excluded.
- Each New Est. and Old Est. independently receives a colored label with a black outline.
- Made Facebook posted and Discovered timestamps bold, with seconds included in the relative ages.
- Replaced the photo's seller classification overlay with **Facebook** and a small blue Facebook icon.
- Display observed mileage immediately and distinguish details still being collected from source checks that found nothing or were unavailable.
- Refresh visible Finder pages on a one-second cadence that includes request duration. Requests do not overlap, errors back off, and hidden tabs pause polling.
- Preserve the user's list position, image elements, and expanded descriptions during updates.
- Share concurrent requests for the same page and measure the short cache window from request start, so slow responses do not create additional stale-cache delay. Session validation remains per request.

## Deal classification

Both estimates use the same rules independently:

| Label | Rule |
| --- | --- |
| Steal | Asking price is at or below the estimate. |
| Good | The price exceeds the estimate by no more than $3,000 **and** 10% of asking price. |
| Potential | Does not qualify as Good; the gap is no more than $5,000 **and** 20% of asking price. |
| Entertain | The price exceeds the above limits. |
| Unknown | No usable positive estimate, or an invalid/missing asking price. |

## Scanner and backend changes

The companion [Carflex Radar repository](https://github.com/Ramthh/carflex-radar) contains the scanner, migration, and worker changes:

- Save discovered cars and available source fields before pricing; create the detail job in the same transaction.
- Preserve exact-item mileage and full descriptions from discovery responses and compatible detail captures.
- Prioritize the newest discoveries for detail checks, retaining older/retry slots.
- Use the configured proxy for detail reads. Ready pages finish immediately; slower pages receive a bounded readiness check before missing-field conclusions.
- Reduce redundant valuation writes and separate full dealer refreshes from urgent queue maintenance.

## Verification and limitations

Twelve Finder tests and the production Next.js build passed. The deployed website code is commit `97378cf`. The live page showed 24 Facebook icon badges and no error banner after the updates.

The accompanying backend full suite passed 1,220 tests; subsequent queue and readiness changes passed their focused checks. In a five-minute observation, 40 new cars were saved and queued, and 16 received both mileage and description before the observation ended. Successful detail arrivals had a median of 21.8 seconds. The sample included rollout startup, excluded unfinished cars from the successful-arrival timing, and preceded the final readiness guard. It is not a controlled comparison with earlier measurements.

**Same-second complete details and finding every ad ahead of other services are not guaranteed.** Facebook often omits mileage and description from search responses, requiring a separate ad load. Queueing, page failures, and server capacity still add delay. Polling cadence is not a guarantee of one-second browser display.

The database remains in place. This notes-only commit does not change application behavior or deploy infrastructure.
